RTI ZRP-6 I/O

Turns an RTI ZRP-6 running the custom MQTT firmware into Control4 connections: seven IR outputs (each switchable to one-way serial), two RS-232 ports, three relays, three 12 V triggers and three contact inputs. It also receives RTI 433 MHz remote buttons and maps them to Control4 room actions and programming events.

Setup

  1. Connection Mode: Direct to box (P2P), the default, logs in to the box itself (below). Central broker logs in to a house MQTT broker that bridges to the box: set Broker Host, Broker Port, Broker Username, Broker Password and Broker Base Topic (the box and discovery properties are hidden in that mode). The broker connects to the box as one MQTT client; give its bridge a client ID starting with ! (e.g. remote_clientid !bridge-house-zrp6, with topic zrp6/# both 0 and try_private false) so the box never bumps it. This driver's own client ID is !c4-zrp6-<device id>.
  2. The box announces itself over mDNS. Box lists the boxes heard and the first one is picked; with several, pick yours. The driver remembers it by MAC and follows it when its DHCP address changes. Box IP Address (an address, or a name like zrp6-7A36.local) overrides discovery; leave it empty to use the discovered box. Discovery Status shows whether announcements are being heard; if none are, type the address. Leave MQTT Port at 1883.
  3. Set Username / Password to a user on the box (a new box has admin / admin).
  4. Base Topic must match the box (default zrp6, at most 11 characters).
  5. Connection Status shows Connected when the driver is logged in. The driver holds exactly one of the box's four sockets and reconnects on its own with a growing delay; after a refused login it waits 30 s.

IR ports as serial

Set IR n Mode to Serial (one-way) to switch a port. Its IR_OUT connection is replaced by an RS_232 connection (re-make the Composer binding after switching), and the driver tells the box (ir/<n>/mode/set). IR n Serial Baud Auto uses the bound device driver's serial settings when the controller can read them (OS 4.2 and later), otherwise 9600. Polarity: RS-232 idles low, TTL idles high.

The box is the source of truth for port settings. They can be changed here in Properties, on the box's web page, or over MQTT. Whenever the box reports its settings (on every connect, and whenever they change), the driver adopts them: the IR and RS-232 properties and the IR_OUT / RS_232 connections change to match, and nothing is sent back. The driver sends a port setting to the box only when you edit it here (and the box has a different value), when a port set to Auto gets a bound device with different serial settings, or when you run Resend Port Configuration. Box Port Settings shows what the box last reported.

Control tab

The Control tab drives the box directly: relay and 12 V trigger states with On / Off / Pulse (Pulse uses Relay Pulse Time), live contact states, each IR port's mode with a Send box (a Pronto or nec <addr> <cmd> code in IR mode, text with an escapes toggle in serial mode), and each RS-232 port's settings with a Send box and the last data received. The header shows the connection, the address in use, the connection mode and the box's firmware.

Remote buttons

Remote buttons are managed only on this driver's Remote Buttons tab (next to Properties). Press Learn a button, press a button on the RTI remote, name it, and add actions: pick a room, then one of that room's Control4 commands as Director lists them (with inputs for its parameters), Select source... (the room's Watch and Listen sources) or Programming event only. A START/STOP pair such as volume up shows once as "(tap)" and sends both. Each remote gets its own list, told apart by the code's preamble; the bench remote's codes have none. Recent presses lists the last codes received, with Add for any not learned yet. Edit, Test and Delete work per button, and Rename remote names a remote.

Every press fires Remote Button Pressed, plus Button: <remote> / <name> for a learned button or Unmapped Remote Button Pressed for one that is not. Variables LAST_REMOTE_CODE, LAST_REMOTE_BUTTON and LAST_REMOTE_NAME hold the last press.

Notes

Serial data received on RS-232 1/2 is available to programming (variable and event). Passing it back to a bound two-way serial device driver is not implemented. If a bound device's commands do not go out, turn on Debug Mode and check Last Unhandled Proxy Command.
